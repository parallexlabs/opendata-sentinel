# Network policy and retry limits

Implementation descriptions below are local observations, externally unverified until independently tested. The implemented portal API is [OpenDataSoft Explore v2.1](https://help.opendatasoft.com/apis/ods-explore-v2/). Socrata support is not claimed; its [SODA endpoints](https://dev.socrata.com/docs/endpoints) are a different API. Legacy internal callable/module names are retained for compatibility.

Source adapters, live benchmark counts/rules and snapshot downloads use the shared redirect transport. It rejects a changed scheme, host or port before sending the redirected request, validates same-origin destinations, limits redirect chains to ten hops, strips the Authorization header and closes intermediate responses. Initial URL checks reject DNS answers in private/reserved ranges. Benchmark requests additionally restrict the initial host to `opendata.vancouver.ca`. Mock-only regressions exercise these paths without contacting private networks.

DNS validation is separate from the connection's DNS resolution: validated addresses are not pinned to the socket. DNS rebinding and changes between validation and connection remain a boundary. These checks are not a complete SSRF guarantee. See [HTTPX transports](https://www.python-httpx.org/advanced/transports/) for the underlying transport interface.

The rate-limited source client defaults to three retries, a 30-second maximum individual retry wait, a 60-second cumulative retry-sleep budget and a 120-second elapsed request/retry budget. These constructor settings must be finite and nonnegative, with positive request timeout/elapsed budget. Numeric `Retry-After` values are capped; negative values become zero; malformed/non-finite values and HTTP-date headers use capped exponential fallback. The last retryable response is returned when the budget is exhausted, so normal status checking still exposes failure.

Elapsed budget checks stop subsequent attempts and cap each HTTPX timeout phase by the remaining budget. They do not forcibly cancel in-progress DNS/transport work or impose a hard wall-clock deadline on a streamed response. HTTPX timeouts govern connect/read/write/pool operations, as described in [HTTPX timeout documentation](https://www.python-httpx.org/advanced/timeouts/). The live benchmark/snapshot clients use guarded redirects and request timeouts; they do not use the source adapter's retry loop. Offline reproduction makes no portal request.
